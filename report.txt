API CONTRACTS VERIFIED FROM THE SIBLING SERVER SOURCE (all GET, /api prefix)
Routes, controllers, services, constants, auth middleware/models and history
aggregation were inspected. The response envelope is { success, data }; Axios
already unwraps the HTTP response body. These are repository contract checks,
not authenticated live-server acceptance tests.

Employee only:
  /employees/dashboard: startDate, endDate, period=week|month.
    Returns tasks, workHours, leaveBalance, performanceTrend and period.
    Identity is taken from authentication; no identity selector is exposed/sent.
  /employees/tasks: startDate/endDate filter createdAt; page, limit supported.
    All pages are fetched before counting status totals. Pagination is
    { page, pages, total, data }. A failed/changing/incomplete result is not shown
    as a complete aggregate.
  /tasks/overdue: current authenticated user's unpaginated overdue list; no forTeam
    parameter is sent. Open statuses are todo/in_progress, with deadline < now.

Team lead:
  /teams/:teamId/members/progress: startDate/endDate, filters task createdAt.
  /teams/:teamId/performance: current/all-date snapshot; accepts no date filter.
  /teams/:teamId/overdue: page, limit; returns data, total, page, pages.
    Backend resolveAccessibleTeam verifies the caller actually leads that team.
    No requests are sent when no team is assigned. No HR-only routes are called.

HR only:
  /statistics/overview: current company snapshot, no filters.
  /statistics/attendance: explicit range OR legacy month/year, company-wide.
  /statistics/leaves: explicit range OR legacy year/month, company-wide.

    explicit range is supplied. Dashboard always supplies its explicit range.
  /statistics/tasks: startDate, endDate, teamId, employeeId, status, priority.
  /statistics/performance-trends: range, teamId, employeeId, period=week|month.
  /statistics/team-performance: range, teamId, employeeId (no status/priority).

  /teams: all pages of nested pagination.total/totalRecords/current are read for

METRIC MEANING AND BACKEND GAPS
- Employee completed/work hours/trend reflect the selected period. In-progress,
  overdue and leave balance are explicitly marked current. The server/model has
  a default 12-day annual balance; the frontend does not invent a leave allowance.
- Team on-time completion uses the latest done event and its deadline snapshot,
  divided by completed tasks having both dates. Legacy tasks lacking history are
  excluded. The server returns 0 when none qualify; denominator/coverage is not
  exposed, so the UI explains that convention rather than claiming full coverage.
- Task cohort reports filter creation time; event trends filter recorded history
  time. These are labelled separately. Dates are YYYY-MM-DD in the local server
  calendar. Trend labels are retained; leave month grouping follows backend UTC.
- Attendance onTimeRate is supplied by the server using present records divided
  by stored records plus calculated absences. Work hours are recorded hours.
- Employees on leave is the backend distinct-person count for approved overlapping
  leave, not request count, days off or employee departures. Pending count is current.
- Team trend remains explicitly unsupported. HR /statistics/performance-trends
  cannot be called by a team lead. Even all pages of /tasks/team/:teamId cannot
  reconstruct the server's historical metric: it lists currently assigned,
  non-deleted tasks, whereas task-history.service scopes statusHistory.teamId
  across historical events, including tasks subsequently moved/deleted.
  Backend addition needed: an ownership-authorized historical aggregation with
  startDate/endDate/period and period/label/totalTasks/completedTasks/completionRate
  trend rows, using the existing history service. No invented endpoint was called.
- Department activity/rankings remain explicitly unsupported. Available department
  data is headcount only. A backend aggregate needs department identity, validated
  task/attendance activity measures, documented denominators and date/scope filters.
  Team completion rankings are shown as teams, not relabelled departments.
- Overdue is not deadline postponement frequency. No reliable deadline-change
  history/count is exposed, so lists show days overdue only. No overload threshold
  is defined; the UI ranks open work without labelling anyone overloaded.
- HR overdue counting currently replaces the requested status in the backend.
  The frontend marks that metric unavailable when a status filter is selected.
  Backend fix needed: intersect the requested status with open statuses, rather
  than replacing it. Other task metrics continue to use all supported filters.
- Team current performance/overdue endpoints do not support range/member filters.
  Those filters are not sent or implied. Attendance/leave cannot be team-filtered.
