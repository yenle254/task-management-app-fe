Dashboard requirement audit — updated 2026-10-24

STATUS
Dashboard source requirements have been reviewed against prompt.txt. Frontend and
backend regression tests, actual HTTP/MongoDB integration, and browser checks of
the real Dashboard components pass within the scope documented below. An expired
session bug was fixed: a matching 401 now clears React authentication state as well
as stored credentials, returning the user to sign-in. A stale earlier-session 401
does not clear a newer account's token. Team trend requests now omit unsupported
identity filters. Existing changes, including system-admin routing, are preserved.
Full acceptance is NOT complete: whole-app web export, native device behavior and
Figma comparison remain blocked/unverified. No Git commit/history operation occurred.

Prompt 4 — team lead dashboard
  Implemented: authorized team current totals/status, member progress, workload
  ordering, paginated overdue tasks/days overdue, selected-period member progress,
  and weekly/monthly history completion trend.
  Implemented: new GET /api/teams/:teamId/performance-trends uses recorded status
  history and resolveAccessibleTeam ownership checks. It accepts startDate/endDate
  as a pair and period=week|month (default grouping is monthly; default range is
  the most recent six calendar months). Rows contain period/label, createdTasks,
  completedTasks, totalTasks, completionRate, onTimeTasks and onTimeRate. Buckets
  without recorded create/complete activity are not fabricated. Historical team
  scope relies on captured statusHistory.teamId; legacy tasks without history are
  omitted.
  Implemented: team on-time metrics now expose onTimeEligibleTasks and onTimeTasks.
  The rate denominator is completions with both a completion event and due-date
  snapshot; known empty denominators display unavailable, while measured zero remains
  zero.
  Implemented fallback for missing business rules: workload is ranked by open task
  count without asserting overload, and overdue work shows elapsed days rather than
  inventing deadline-extension counts.
  Verified: actual own-team and HR access; other lead and employee denied on all
  four team Dashboard endpoints. Fixtures verify shared assignments, date cohorts,
  oldest-first pagination, moved/deleted historical events, repeated completions,
  and on-time coverage (1 / 3 eligible completions = 33.33%).

Prompt 4 — HR dashboard
  Implemented: company overview, attendance on-time rate/distribution/trend, leave
  counts (distinct employees on approved leave, current pending requests), task
  statistics, performance trend, team completion ranking, current active department
  headcount ranking, and department task activity.
  Implemented: new HR-only GET /api/statistics/department-activity accepts optional
  startDate/endDate pair, teamId and employeeId. It groups tasks created in the
  selected range by the current department of active assignees and returns
  department, totalTasks, completedTasks, openTasks and overdueTasks. Each task is
  counted once per department; shared tasks across departments appear once in each
  involved department. The dashboard charts/ranks by total task count and shows the
  status counts in a table. Date filters apply to activity, not current headcount;
  status/priority apply to task statistics only. Team/employee scope is applied on
  the server-side task query. This is a task-activity measure, not an attendance or
  productivity measure.
  Implemented: endpoint is protected by existing HR authorization middleware.
  Verified: distinct approved leave people (2 people / 3 records), task status and
  priority intersections, current department grouping and per-department task
  deduplication through actual MongoDB. Nonzero attendance verifies 19.5 total
  recorded hours, present=2, late=1, calculated weekday absences, daily totals and
  the existing present/total-records on-time denominator, including legacy calls.
  Qualification: this validates aggregation of stored attendance statuses and the
  existing absence policy, not GPS clock-in, office shift setup or holiday policy.

Prompt 5 — filters/data semantics
  Implemented: date presets/ranges, supported team/member filters, task status and

  Implemented: stale request/cache guards, in-flight deduplication, isolated errors,
  retry, current-vs-period labels, paginated reads before aggregation, and no fake
  production data or client-side permission filtering.
  Implemented: no false zero for API errors, malformed/missing data or empty rate
  denominators. Shared task assignment counts once per assignee in member workload;
  department activity deduplicates per department.
  Backend qualification: department classification uses current active assignee
  profile.department, not historical department membership. Changes to employee
  department are not historically recorded for this report.
  Verified in browser: team changes reset the member selector; date ranges/presets
  load real results; inverted dates show validation; a delayed current-month task
  response cannot replace a newer last-month selection. Injecting an attendance

  Empty/zero source data and nonzero isolated data were both exercised. Missing
  fields, malformed values and unavailable denominators are covered by unit tests,
  not claimed as naturally occurring records in the source database.
